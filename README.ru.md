# Comfy SynthID Remover

Локальный img2img-пайплайн для [ComfyUI](https://github.com/Comfy-Org/ComfyUI). В репозитории есть готовые workflow и CLI для обработки отдельных изображений и целых папок.

Изображение проходит через диффузионную модель и сохраняется после реконструкции. Это может повлиять на невидимые водяные знаки, в том числе SynthID, но **гарантии удаления нет**. Детектор SynthID в проект не входит. При реконструкции могут измениться текстуры, надписи и мелкие детали.

[English documentation](README.md)

## Быстрый запуск

1. Установить и запустить [ComfyUI](https://github.com/Comfy-Org/ComfyUI).
2. Установить совместимые веса диффузионной модели, текстового энкодера и VAE (см. [Модели](#модели)).
3. Перетащить [`workflows/optimized.json`](workflows/optimized.json) в окно ComfyUI.
4. Выбрать установленные модели и исходное изображение в **Load Image**.
5. Нажать **Run**. Результат сохранится в `ComfyUI/output/` с префиксом `SynthidImg2Img`.

В оптимизированном workflow используются стандартные ноды ComfyUI. Дополнение для сохранения изображений не требуется.

## Модели

По умолчанию граф рассчитан на конфигурацию Z-Image с текстовым энкодером Qwen3-4B. В нодах указаны следующие имена файлов:

| Каталог ComfyUI | Имя файла |
| --- | --- |
| `models/diffusion_models/` | `moody-pro-signature-004_00001__clean_convrot_int8.safetensors` |
| `models/text_encoders/` | `qwen3-4b_int8_convrot_fp16emixed.safetensors` |
| `models/vae/` | `ae.safetensors` |

Веса в репозиторий не входят. Можно выбрать другие совместимые файлы в нодах либо передать их имена через CLI. Для INT8-чекпоинтов может потребоваться поддержка соответствующей квантизации в ComfyUI. Стандартные веса доступны в [коллекции Comfy-Org Z-Image Turbo](https://huggingface.co/Comfy-Org/z_image_turbo); с другими моделями может потребоваться изменить настройки загрузчиков.

У **CLIP Loader** выбран тип `lumina2`, у **ModelSamplingAuraFlow** выставлены `shift = 3` и `flow`. Эти настройки должны соответствовать используемой модели.

## Workflow

| Файл | Назначение |
| --- | --- |
| [`workflows/optimized.json`](workflows/optimized.json) | Основной вариант на 6 шагах, только стандартные ноды. |
| [`workflows/fast-4step-experimental.json`](workflows/fast-4step-experimental.json) | Вариант на 4 шагах для экспериментов со скоростью. |
| [`workflows/original.json`](workflows/original.json) | Полный исходный граф с дополнительной нодой `SaveImageAdvanced`. |
| [`api/prompt.json`](api/prompt.json) | Граф для запуска через HTTP API. |

Стандартные параметры: `steps = 6`, `cfg = 1`, `res_multistep`, `karras`, `denoise = 0.6`, `shift = 3`, пустой промпт.

В `optimized.json` один `CLIP Text Encode` подключён к `positive` и `negative`. При `cfg = 1` отрицательный conditioning не участвует в classifier-free guidance, поэтому второй энкодинг такого же пустого текста лишний. Загрузка текстового энкодера для первого запуска всё ещё нужна.

## Запуск из терминала

Нужны Python 3.9+ и запущенный сервер ComfyUI. Установка дополнительных Python-пакетов не требуется.

Одно изображение:

```bash
python cli.py -i input.webp -o output.png
```

Папка с изображениями, без вложенных каталогов:

```bash
python cli.py -i ./input -o ./output --steps 4 --denoise 0.6
```

Другие модели:

```bash
python cli.py -i input.webp -o output.png \
  --model z_image_turbo_bf16.safetensors \
  --clip qwen_3_4b.safetensors \
  --vae ae.safetensors \
  --scheduler simple --seed 42
```

Дополнительные параметры: `--server` (по умолчанию `http://127.0.0.1:8188`), `--prompt`, `--shift`, `--timeout`, `--poll`, `--api-prompt`. Полный список: `python cli.py --help`.

CLI загружает входные изображения через `/upload/image`, отправляет задания на `/prompt`, отслеживает выполнение через `/history/{prompt_id}` и получает результат через `/view`. Папка обрабатывается последовательно, чтобы ComfyUI мог переиспользовать загруженные модели. Сервер лучше держать локальным: в CLI нет аутентификации.

## Настройка и проверка

Снижение `steps` с 6 до 4 сокращает количество проходов диффузионной модели, но может ухудшить сохранность деталей. `denoise` управляет степенью реконструкции. Для сравнения разных настроек стоит фиксировать `--seed`.

Отрицательный ответ детектора SynthID **не доказывает полного удаления метки**. В репозитории нет измерений доли успешного удаления. Для оценки результата нужно отдельно сравнить качество изображения и показания детектора.

Проверка структуры графов и CLI:

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют связи нод, API-граф, параметры CLI и имитацию HTTP-запросов к ComfyUI. Они не запускают диффузионную модель и не проверяют удаление SynthID.
